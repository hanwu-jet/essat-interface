# 四篇论文，怎样让人参与 AI 的工作？

以 option2 为主线，用同一个日常通勤例子，对照另外三篇论文的不同交互重点。淡白底色，明尼苏达大学猩红与玉米黄作点缀。

## 建议演示顺序

1. **锚点论文：看过结果，再改想法。** 初始要求是 3 公里、25 分钟内、最多 20 元，先求最快。页面优先显示打车。看到打车 18 元、骑车 2 元的取舍，点击“准时就行，选便宜的”，优先方案改为共享单车，并显示前后变化。这把“重新决定什么算好结果”落到真实可操作的判断标准上。
2. **AIChains：找到具体哪一步要改。** 把公交等车时间从 5 改为 12 分钟，只更新这一中间结果与后续判断。公交总时长从 25 变为 32 分钟；其他走法保留。
3. **Cocoa：决定哪一步由我来做。** 将确认等车时间分配给“我来填写”，执行共同计划。流程会停下来等待，直到人提供数值；随后用这个数值重新比较，并标明“由你提供”。
4. **Magentic-UI：执行时仍能接手。** 按一个符合要求的方案逐步试运行；可暂停、更换走法并恢复。付费前显示当前方案和金额，只有模拟确认后才继续；取消会停止。步行没有付费确认。

四种体验共享条件和结果，切换论文不会重置数据。“恢复示例”会重置条件、操作记录、分工和模拟执行。

每个体验旁都有“论文里 / 你在这里做的事 / 对锚点论文的补充”，以及可展开的章节、PDF 页码和原文链接。顶部“对照论文与出处”提供四篇的比较表与详细证据。进一步的来源映射见 `SOURCES.md`。


## 打开与发布

双击 `index.html` 即可使用，文件需保持在同一目录。也可以使用任意静态服务器。无需安装依赖，输入不会发送到外部，刷新后恢复初始状态。

发布到 GitHub Pages：把全部文件放进公开仓库根目录，确保根目录直接有 `index.html`。在 Settings → Pages 中选择对应分支及根目录。资源均使用相对路径，支持项目子目录。
