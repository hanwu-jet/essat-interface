# 四篇论文，怎样让人参与 AI 的工作？

以 锚点论文 为主线，用同一个日常通勤例子，对照另外三篇论文的不同交互重点。淡白底色，明尼苏达大学猩红与玉米黄作点缀。

## 建议演示顺序

1. **锚点论文：看过结果，再改想法。** 初始要求是 3 公里、25 分钟内、最多 20 元，先求最快。页面优先显示打车。看到打车 18 元、骑车 2 元的取舍，点击“准时就行，选便宜的”，优先方案改为共享单车，并显示前后变化。这把“重新决定什么算好结果”落到真实可操作的判断标准上。
2. **AIChains：找到具体哪一步要改。** 把公交等车时间从 5 改为 12 分钟，只更新这一中间结果与后续判断。公交总时长从 25 变为 32 分钟；其他走法保留。
3. **Cocoa：决定哪一步由我来做。** 将确认等车时间分配给“我来填写”，执行共同计划。流程会停下来等待，直到人提供数值；随后用这个数值重新比较，并标明“由你提供”。
4. **Magentic-UI：执行时仍能接手。** 按一个符合要求的方案逐步试运行；可暂停、更换走法并恢复。付费前显示当前方案和金额，只有模拟确认后才继续；取消会停止。步行没有付费确认。

四种基本操作共享条件和结果，切换论文不会重置数据。“恢复示例”会重置条件、操作记录、分工、模拟执行与全部小实验。

## 从论文发现出发的小实验

每篇有“基本操作 / 发现 1 / 发现 2”三个入口。小实验使用各自左侧列出的固定条件，独立保存进度；返回自由比较会保留原先输入。所有实验使用本地规则，没有连接语言模型、地图或支付服务。

| 论文 | 发现 1 | 发现 2 |
| --- | --- | --- |
| 锚点论文 | 全部失败时，加入距离目标的反馈；硬条件仍不满足 | 查出漏算时间，修正评价规则，重新判断候选 |
| AIChains | Sandbox 文本入口与明确步骤入口，都能修正同一数据 | 对照计算路径，补回遗漏，更新相关判断 |
| Cocoa | 先看估算结果，再修改并执行下一步 | 流程等待人的站点信息；后续真实使用该产物 |
| Magentic-UI | 区分接受报告、查看依据和使用核对值 | 全部记录与待处理筛选，确认或取消模拟费用 |

每个实验附原文发现、具体例子、研究方法、PDF 页码，以及教学改编的范围。锚点的基本操作还明确说明：本页预设的方案生成规则并未复现 AlphaEvolve 的初始程序演化；判断条件与排序仅类比评价函数的一部分。

每个体验旁都有“论文里 / 你在这里做的事 / 对锚点论文的补充”，以及可展开的章节、PDF 页码和原文链接。顶部“对照论文与出处”提供四篇的比较表与详细证据。进一步的来源映射见 `SOURCES.md`。


## 打开与发布

双击 `index.html` 即可使用，文件需保持在同一目录，包括 `lessons.js`、`lessons-cocoa.js`、`lessons-magentic.js` 和 `lessons.css`。也可以使用任意静态服务器。无需安装依赖，输入不会发送到外部，刷新后恢复初始状态。

发布到 GitHub Pages：把全部文件放进公开仓库根目录，确保根目录直接有 `index.html`。在 Settings → Pages 中选择对应分支及根目录。资源均使用相对路径，支持项目子目录。
